# Live Cloud Asset Sync, Mobile QR Spec Sheet, Inventory Import & QA Inspection Suite

Comprehensive implementation plan to upgrade TradeTech Bench with real-time multi-device Firestore synchronization for all hardware assets, a standalone mobile-friendly diagnostic spec sheet generated by QR code bench stickers, a bi-directional JSON/CSV inventory import engine, visual Kanban board asset organization, and an official Quality Assurance (QA) workbench for Julian and Kylin.

---

## User Review & Critical Decisions

> [!IMPORTANT]
> The following product and technical decisions have been synthesized directly from your prompt and interactive clarifications:

- **Standalone Mobile QR Spec Sheet**: Scanning the printed QR bench sticker with any smartphone or handheld camera now directs to a dedicated, responsive Asset Passport URL (`/?asset=TAG`). It renders the hardware's complete diagnostic history, full component specifications, live bench location, and QA verification seal without requiring manual navigation.
- **Real-Time Cross-Device Synchronization**: All hardware assets will sync in real time using a live Firestore `onSnapshot` listener on the provisioned database. When any technician adds, edits, or inspects a device on any computer, phone, or tablet, every screen in the vocational lab updates instantly.
- **Asset Import Engine**: Complements the existing JSON exporter with a robust file import handler supporting both `.json` and `.csv`. Includes a validation preview modal with conflict resolution (Merge vs Replace) and batch Firestore commits.
- **Dual Organization Views (Multi-Filter & Kanban)**: Hardware assets can be viewed either as a dense diagnostic table/grid with multi-criteria filtering (Status, Bench, Category, QA Stage, Physical Presence) or as an interactive Kanban workflow board (Intake, In Triage, Bench Repair, Awaiting QA, Passed & Deployed).
- **Quality Assurance Role (Julian & Kylin)**: A new `quality_assurance` vocational role assigned to Julian and Kylin, featuring a 10-point hardware checkoff checklist, official digital QA pass/fail seal stamping, and a historical inspection sign-off log.

## 1. Overview & Core Concept

### What It Does
1. **Live Cloud Inventory**: Migrates local asset state to real-time Firestore persistence with instant bi-directional updates across all student workstations, mobile devices, and the teacher console.
2. **Mobile QR Scanner Destination**: Turns every printed bench sticker into a live scannable link opening a clean, standalone hardware spec sheet showing diagnostic metrics, physical presence status, and QA approvals.
3. **Bi-directional Data Portability**: Enables instructors and lab managers to export and re-import complete asset rosters via `.json` or `.csv`.
4. **Visual Kanban & Flexible Filtering**: Provides technicians and foremen with clear visual swimlanes to track device repair progression from intake to QA sign-off.
5. **Quality Assurance Workbench**: Equips Julian and Kylin with specialized tools to enforce rigorous quality standards before any repaired device is returned to service.

### Target Audience & Persona
- **QA Inspectors (Julian & Kylin)**: Review repaired laptops, desktops, and lab equipment; run functional verification; apply official pass/fail sign-offs.
- **Bench Technicians & Students**: Scan QR codes on physical devices to instantly read specs, report faults, and update repair stages.
- **Instructor (Mr. McKismic) & Asset Managers**: Import class batches of incoming donated hardware, organize lab inventory, and monitor live bench status.

## 3. Key Product Decisions & Trade-Offs

### Decision 1: URL Structure for QR Code Destination
- **Chosen Approach**: `${window.location.origin}/?asset=${assetTag}`
- **Why**: Works universally across standard phone cameras, barcode readers, and web browsers without requiring complex server router rewrites. When the URL contains `?asset=...`, the app renders a dedicated full-screen `AssetPublicSpecSheet` with a "Back to Lab Console" navigation option.
- **Alternative Considered**: Generating raw JSON in the QR code. Rejected because native camera apps cannot navigate or render rich interfaces from raw JSON strings.

### Decision 2: Real-Time Sync via Firestore `onSnapshot`
- **Chosen Approach**: Mount an active Firestore `onSnapshot` listener on the `hardware_assets` collection inside `AppContext`. If the remote database is initially empty, seed it with `INITIAL_HARDWARE_ASSETS`. All writes (`save`, `update`, `delete`, `import`) write directly to Firestore.
- **Why**: Guarantees zero latency and instantaneous synchronization across all devices and browser tabs for all technicians.

### Decision 3: Asset Import Strategy
- **Chosen Approach**: Parse both `.json` (array or TradeTech export envelope) and `.csv` files. Present an interactive preview modal displaying newly discovered items vs existing records, allowing the user to choose "Update existing & add new" or "Add only new".
- **Why**: Prevents accidental data loss while giving users maximum flexibility when importing batch files.
